# S1: pass counting on Metrica pro games (29 Sep 2026)

**Answer key:** Metrica's two free pro games (4 halves, 1,763 hand-labelled passes). Each of our passes is matched to one of their PASS events: same team, released within 1 s.
**Noise:** "clean" = their exact positions. "streak" = our Veo tracking errors: the ball is missing or wrong in runs, about 7 of 11 players are seen per team, and positions wobble.
**Tool:** `tools/passlab.py` (free, runs on the CPU). Raw numbers are in `results/metrica/passlab_{grid,fine,states,possession_*}.json`.

## What was wrong

The pass count looked fine (3-13% off), but only because two big errors cancelled out. Only **61%** of the real passes were found, and only **65%** of our passes were real.

- **Missed passes (39%)**, mostly ordinary 1-2 s passes. When the ball rolls past an opponent (within 2.5 m) for a few frames, we counted that as a touch. So one pass A1 → A2 became "A1 lost it, then A2 won it back", and no pass was counted. The same happened when a wrong ball pick landed next to an opponent for a moment.
- **Extra passes (35% of ours)**: mostly in duels and scrambles (a tackle, a block, a loose ball), where Metrica logs "ball lost / recovery" instead of a pass. There were also 1-4 m "passes" between two teammates standing close together.

## The fix (now the default in `analytics.passes`)

1. `team_sandwich_s=0.3`: an opponent's contact shorter than 0.3 s between two contacts of the same team counts as the ball running past him. It is dropped, so the pass between the teammates is counted.
2. `min_pass_m=5`: a ball move shorter than 5 m between two players is not a pass.

Setting either one to 0 gives the old behaviour. Tests: `tests/test_passes_s1.py` (6 tests). The full test suite passes (93 tests).

- On all 8 runs, the new rule finds more real passes and adds fewer false ones.
- The count is within 7.4% on 7 of the 8 runs. The one exception is game 2, first half, with streak noise: 8.6% under. So the ~7% goal is met on 7 of 8 runs.
- Game 1 now counts a few too many passes (+2 to +7%) and game 2 a few too few (0 to -9%). That split is the same whatever the settings, so no single setting fixes it (grid of ~150 settings in `passlab_grid.json` and `passlab_fine.json`).
- Possession % and lost balls do not change. Passes are computed after them and feed nothing back.
- Our own SFK-BP clip (5 min, no pass answer key): 123 → 111 completed passes.

**What is still missed / added (all 8 runs):**
- Still missed: headers 57%, very quick passes (under 0.6 s) 47%, passes right after a duel 45%, one-touch passes 38%, long balls 37%, set pieces 30%, ordinary passes 23% (was 37%).
- Extra passes: 956 in total (was 1,178). 435 are in duels or loose balls. 267 sit within 3 s of a real pass: mostly the right pass logged more than 1 s off in time, sometimes one pass counted twice.

**Tried, not adopted:**
- Dropping a short contact by a teammate (the ball running past him): kills one-touch passes.
- A "did the ball change direction" test for short contacts: it separates cleanly on clean data. But Metrica's clean ball runs in straight lines between touches, which flatters this test, and under noise it made things worse.
- Both are kept as options: `mate_sandwich_s` and `pass_by_mps` (off).

## Old model vs possession_simple as the state for passes

On Metrica, possession_simple was run as the other agent will run it: H = identity, metres used as pixels, near_m = 1.5, smooth = 6.

| Way to use the state (all 8 runs) | Worst count error | Real passes found | Our passes real |
|---|---|---|---|
| New rule, no state (the default)                                 | 8.6%  | 73% | 73% |
| New rule + ignore touches that possession_simple disagrees with  | 9.9%  | 74% | 74% |
| New rule + ignore touches the old model disagrees with           | 14.9% | 75% | 73% |
| Carrier taken from possession_simple (its team's nearest player) | 74% under with noise | 49% | 85% |
| Carrier taken from the old model                                 | 96% under with noise | 37% | 85% |

**Verdict:** possession_simple is the better state (9.9% vs 14.9% worst error), but neither beats counting passes straight from ball contacts. Passes should keep using the contacts. So switching the pipeline to possession_simple does not change pass counts at all.

Building carriers from either state fails under noise, because the state says "loose" 73-87% of the time. Passes are very accurate but far too few.

**Warning for E4 (lost balls with possession_simple):**
- With the default 3 s + 3 s rule, possession_simple finds almost no lost balls on Metrica: 6-10 per half on clean data (truth 105-142). The old model finds 29-49.
- With a 1 s + 1 s rule it finds 46-63 (34-50 correct), about the same as the old model's correct ones on clean data.
- Under streak noise both are near zero, as found in S1b.
