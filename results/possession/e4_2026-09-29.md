# E4: possession_simple is now the pipeline default (29 Sep 2026)

**What changed:** `ipanema/run.py` now gets "who has the ball" from `possession.pipeline_state`, which uses
possession_simple (nearest feet to the ball in the picture). The old model is still there: set
`IPANEMA_POSSESSION=viterbi` to switch back. The app picks this up at the next paid run (A1).

- Lost balls (turnovers) now use a 1 s + 1 s hold rule. With the old 3 s + 3 s rule the new model finds 0 on both clips (S1 warned about this on Metrica).
- Restarts (set pieces) still come from the old model's "dead ball" state. The new model has no "dead ball" state. Copying the old model's dead-ball stretches in would put 13 of the 99 key moments (all in play) into "dead", so they are not copied.
- Passes are unchanged. They are counted from ball contacts, not from the possession state (S1).

**Tool:** `tools/e4lab.py` (local, free, 30 s). It runs the same steps as run.py on the SFK-BP clip and the Reymersholm clip (5 min each).
Raw numbers: `results/possession/e4_2026-09-29.json`. Tests: `tests/test_possession_default.py` (7 tests).

**What got better:** "who has the ball" is right about twice as often on SFK-BP and 4 more times on Reymersholm. Lost balls now show up at all: 19 and 18 in 5 minutes, which is a believable number for a youth game. Before it was 3 and 0. We have no answer key for lost balls on our footage, so how many of them are right is not measured yet.

**What got worse: sequences.** The new state flips between the teams about 190 times in 5 minutes when the ball is between two players. So we count about 3x more sequences, and most of them are under 1 s. I tried removing short flips (0.3-1.5 s) from the state itself. That fixed the count but cost key moments on both grounds (Reymersholm 27 -> 22-24/32), so it is not done. The fix belongs in the sequence counting, not in the state. New queue item E5.

**Not changed:** the nightly check on the pro data (Metrica) still scores the old model (`tools/metricalab.py`). Switching it is part of E5, so the nightly numbers don't jump without a note.

**Checks:** new tests pass (7). The full test suite has 101 passing. 3 fail here only because torch and supervision are not installed on this machine; they are unrelated to this change.
